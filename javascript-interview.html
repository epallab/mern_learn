BEGINNER LEVEL

1. Beginner Questions

Q1: var vs let vs const — what actually differs?
  • var — function-scoped, hoisted and initialized to undefined, re-declarable, attaches to window at top level
  • let — block-scoped, hoisted but uninitialized (the temporal dead zone), reassignable
  • const — like let, but the binding can't be reassigned. The value is still mutable: const arr = []; arr.push(1) is legal 
console.log(a); // undefined (var hoisted + initialized)
console.log(b); // ReferenceError (TDZ)
var a = 1;
let b = 2;
Q2: List the data types. What does typeof get wrong?

Seven primitives — string, number, bigint, boolean, undefined, symbol, null — plus object (arrays, functions, dates are all objects). 

typeof null;        // "object"  — historic bug, memorize it
typeof [];          // "object"  — use Array.isArray()
typeof function(){} // "function" — the one non-primitive special case
typeof NaN;         // "number"
Q3: == vs === — how does coercion decide?

=== compares type and value with no conversion — the default choice. == coerces first: null and undefined equal each other (and nothing else), strings/booleans convert to numbers, objects convert via valueOf/toString. 

0 == "0"        // true   ("0" → 0)
0 == []         // true   ([] → "" → 0)
"0" == []       // false  ([] → "", "0" != "")
null == undefined // true
null == 0       // false — null only equals undefined
Q4: Which values are falsy?

Exactly eight: false, 0, -0, 0n, "", null, undefined, NaN. Everything else is truthy — including "0", [], and {}. That's why if ([]) runs but [] == false is true — different algorithms.

Q5: null vs undefined?

undefined — the engine's "no value yet": missing properties, unassigned variables, functions without return. null — the programmer's deliberate "empty on purpose". JSON has null but not undefined; JSON.stringify drops undefined properties entirely.

Q6: Arrow functions vs regular functions?
  • Arrows have no own this — they close over the enclosing scope's this (that's the point)
  • No arguments object, no prototype
  • Can't be used with new
  • Wrong tool for object methods and event handlers that rely on this being the element 
const timer = {
  seconds: 0,
  start() {
    // arrow keeps `this` = timer; function() would lose it
    setInterval(() => this.seconds++, 1000);
  },
};
Q7: Spread vs rest — same syntax, opposite jobs?

Spread expands an iterable where values are expected; rest collects leftovers where parameters are declared. 

const merged = { ...defaults, ...options };   // spread (shallow!)
const copy = [...arr];                        // spread
function log(first, ...rest) {}               // rest
const [head, ...tail] = list;                 // rest in destructuring
Q8: Destructuring — defaults, renaming, nesting?
const { id, name: label, meta: { tags = [] } = {} } = doc;
//        │        │             └ nested + default for the object itself
//        │        └ rename name → label
//        └ plain pick

function connect({ host = "localhost", port = 27017 } = {}) {}
// = {} lets connect() be called with no argument at all
Q9: map vs forEach vs reduce — when each?
  • map — transform every item, get a new array back. Returns; never mutates
  • forEach — side effects only; returns undefined, can't break early (use for..of if you need to)
  • reduce — fold to a single value: sums, lookups, groupBy 
const byId = users.reduce((acc, u) => {
  acc[u.id] = u;
  return acc;
}, {});
Q10: What are template literals good for beyond strings?

Interpolation `${x}`, real multiline strings, and tagged templates — a function receives the string parts and values separately (how libraries like styled-components and safe SQL builders work). 

const query = sql`SELECT * FROM users WHERE id = ${id}`;
// sql() gets ["SELECT…id = ", ""] and [id] — it can escape id safely
INTERMEDIATE LEVEL

2. Intermediate Questions

Q11: What is a closure? Give a practical use.

A function bundled with its lexical scope — it keeps access to the variables where it was defined, even after that scope has returned. Uses: private state, factories, memoization, debounce, event handlers remembering context. 

function makeCounter() {
  let count = 0;              // private — only reachable via the closure
  return () => ++count;
}
const next = makeCounter();
next(); // 1
next(); // 2 — count survives between calls
Q12: The classic bug: setTimeout inside a var loop?
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i)); // 3, 3, 3 — one shared i
}
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i)); // 0, 1, 2 — new binding per iteration
}

var creates one function-scoped i that has reached 3 by the time the callbacks run. let creates a fresh block-scoped binding per iteration, so each closure captures its own value. (Pre-let fix: wrap the body in an IIFE.)

Q13: How is `this` decided? The four bindings.
  1. new — new Fn(): this = the fresh object
  2. Explicit — fn.call(obj) / apply / bind: this = obj
  3. Implicit — obj.fn(): this = the object before the dot
  4. Default — bare fn(): undefined in strict mode, else the global object

Arrows ignore all four and inherit lexically. Precedence: new > explicit > implicit > default.

Q14: call vs apply vs bind?
greet.call(user, "Hi", "!");       // invoke now, args listed
greet.apply(user, ["Hi", "!"]);    // invoke now, args as array
const bound = greet.bind(user);    // invoke later, this locked in

bind returns a new function permanently tied to that this — a second bind can't override it, and neither can call.

Q15: Explain the prototype chain.

Every object has an internal link (__proto__, officially [[Prototype]]) to another object. Property lookups walk up that chain until found or the chain ends at null. Methods like arr.map live once on Array.prototype, not on every array. 

const arr = [];
arr.__proto__ === Array.prototype;                 // true
Array.prototype.__proto__ === Object.prototype;    // true
Object.prototype.__proto__ === null;               // end of chain
Object.create(proto);  // make an object with a chosen prototype
Q16: class vs constructor function — what's real?

class is syntax over the same prototype machinery — with real differences: class bodies run in strict mode, aren't hoisted usably, must be called with new, and get extends/super plus private #fields. 

class Repo {
  #cache = new Map();            // truly private
  constructor(model) { this.model = model; }
  async find(id) {
    if (!this.#cache.has(id))
      this.#cache.set(id, await this.model.findById(id));
    return this.#cache.get(id);
  }
}
Q17: Shallow vs deep copy — and how to deep copy right?

Spread and Object.assign copy one level; nested objects are still shared references. structuredClone(obj) is the modern deep copy (handles Dates, Maps, cycles). JSON.parse(JSON.stringify(x)) is the old trick — it drops functions and undefined, and breaks Dates.

Q18: for..in vs for..of vs Object.entries?
  • for..in — enumerable keys, including inherited ones; wrong tool for arrays (gives index strings)
  • for..of — values of any iterable (arrays, strings, Map, Set); supports break/continue
  • Object.keys/values/entries — own properties only, as arrays you can chain 
for (const [key, value] of Object.entries(config)) { ... }
Q19: Optional chaining and nullish coalescing?
const city = user?.address?.city;    // undefined instead of TypeError
user?.save?.();                      // call only if it exists
const limit = options.limit ?? 20;   // 0 stays 0 — only null/undefined fall through
const bad   = options.limit || 20;   // 0 becomes 20 — the classic || bug
Q20: ES Modules vs CommonJS?
  • ESM — import/export, static (analyzable → tree-shaking), async loading, strict mode, live bindings
  • CJS — require/module.exports, synchronous, values are copied at require time
  • Browsers speak ESM natively (<script type="module">); Node speaks both ("type": "module" or .mjs to opt in)
ADVANCED LEVEL

3. Advanced Questions

Q21: Walk through the event loop.

One call stack. When it empties, the loop runs the entire microtask queue (promise callbacks, queueMicrotask), then one macrotask (setTimeout, I/O, events), then microtasks again — repeat. Microtasks always beat macrotasks; a microtask that queues microtasks can starve rendering. 

console.log("A");
setTimeout(() => console.log("B"));          // macrotask
Promise.resolve().then(() => console.log("C")); // microtask
console.log("D");
// A, D, C, B — sync first, then microtasks, then the timer
Q22: Promise states and error propagation?

pending → fulfilled or rejected, exactly once, immutable after. Each .then returns a new promise; a thrown error or rejection skips forward to the nearest .catch, and the chain continues fulfilled after it (catch "handles" it). 

fetch(url)
  .then((r) => {
    if (!r.ok) throw new Error(r.status); // fetch doesn't reject on 404!
    return r.json();
  })
  .catch((e) => fallback)   // handles network AND the throw above
  .then((data) => render(data)); // still runs, with fallback
Q23: async/await — what is it really doing?

Syntax over promises: an async function always returns a promise; await pauses that function only, parking the rest as a microtask continuation. Errors become rejections you catch with try/catch. Classic trap: awaiting in sequence what could run in parallel. 

// sequential — 2× latency          // parallel — one round trip
const a = await getA();             const [a, b] = await Promise.all([
const b = await getB();               getA(), getB(),
                                    ]);
Q24: Promise.all vs allSettled vs race vs any?
  • all — resolves with every value; rejects fast on the first failure
  • allSettled — never rejects; gives {status, value|reason} per input — right for "save what you can"
  • race — first to settle wins, success or failure (timeouts)
  • any — first to fulfill; rejects only if all reject (AggregateError)
Q25: Debounce vs throttle — which, when?

Debounce waits for silence: fire once, N ms after the last call — search-as-you-type, resize handlers, autosave. Throttle guarantees a rhythm: at most once per N ms while events keep firing — scroll position, mousemove, analytics. (Implementations are in the Practice section — be ready to write both from memory.)

Q26: Event delegation — why and how?

Events bubble from the target up through its ancestors. Attach one listener on a stable parent and route by event.target — fewer listeners, and dynamically added children work automatically. 

list.addEventListener("click", (e) => {
  const btn = e.target.closest("[data-delete]");
  if (btn && list.contains(btn)) remove(btn.dataset.delete);
});
Q27: Common JS memory leaks?
  • Forgotten listeners/intervals on removed DOM (always clean up in SPA unmounts)
  • Closures pinning large objects a long-lived callback still references
  • Module-level caches/Maps that only ever grow
  • Detached DOM nodes still referenced from JS

WeakMap/WeakSet hold keys weakly — if nothing else references the key, the entry can be collected. Right tool for metadata about DOM nodes.

Q28: What are generators used for?

function* returns an iterator you can pause and resume; yield hands out a value and waits. Uses: lazy/infinite sequences, custom iterables, and consuming paginated APIs one page at a time. 

function* pages(fetchPage) {
  let page = 1, batch;
  do {
    batch = yield fetchPage(page++);   // caller decides when to pull more
  } while (batch.hasMore);
}
Q29: What is currying? Where is it useful?

Turning f(a, b, c) into f(a)(b)(c) — each call locks in an argument via closure and returns a function wanting the rest. Useful for configuration-first APIs and reusable partials. 

const on = (type) => (handler) => (el) => el.addEventListener(type, handler);
const onClick = on("click");
buttons.forEach(onClick(save));
Q30: Why does immutability matter (especially in React)?

Change detection by reference: React, Redux, and memoization all decide "did this change?" with ===. Mutating in place keeps the same reference — updates get skipped. So: copy-and-replace ({...state, done: true}, map/filter over splice/push). Object.freeze is shallow; libraries like Immer give ergonomic deep updates.

Q31: Hoisting — what does this print?
console.log(x);
console.log(getY);
console.log(getY());
var x = 5;
function getY() { return 10; }
// undefined — var hoisted, value not yet assigned
// [Function: getY] — declarations hoist whole
// 10 — callable before its line
Q32: Microtasks vs macrotasks — order?
setTimeout(() => console.log(1), 0);
Promise.resolve().then(() => console.log(2));
queueMicrotask(() => console.log(3));
console.log(4);
// 4  — sync
// 2, 3 — the whole microtask queue drains first
// 1  — then the timer macrotask
Q33: await ordering — what does this print?
async function main() {
  console.log("a");
  await null;            // everything after this line = microtask
  console.log("b");
}
main();
console.log("c");
// a, c, b — await yields back to the caller synchronously
Q34: Extracted method — what does this print?
const user = {
  name: "Ada",
  hello() { return "Hi " + this.name; },
};
const f = user.hello;
console.log(user.hello()); // "Hi Ada"   — implicit binding
console.log(f());          // "Hi undefined" — default binding lost the object
const g = user.hello.bind(user);
console.log(g());          // "Hi Ada"   — bind restores it
Q35: Coercion — what do these evaluate to?
[] + []      // ""        — both become ""
[] + {}      // "[object Object]"
1 + "2"      // "12"      — + prefers strings
"5" - 2      // 3         — - is numeric only
0.1 + 0.2 === 0.3   // false — binary floats; compare with Number.EPSILON
NaN === NaN  // false     — use Number.isNaN(x)
Q36: Closures sharing state — what does this print?
function make() {
  let n = 0;
  return { inc: () => ++n, get: () => n };
}
const a = make();
const b = make();
a.inc(); a.inc(); b.inc();
console.log(a.get(), b.get());
// 2 1 — each make() call creates a fresh scope; a and b don't share n

5. Quick-Fire Round

Question Answer
Reliable NaN check? Number.isNaN(x) — no coercion, unlike global isNaN
Check "is an array"? Array.isArray(x) — typeof says "object"
What does x == null test? null or undefined in one idiom — the useful ==
What is an IIFE? Immediately invoked function — (function(){})() — old scope isolation
What does "use strict" change? Silent errors throw; undeclared assignment fails; this defaults to undefined
Symbol — what for? Guaranteed-unique keys; protocol hooks like Symbol.iterator
Modern deep clone? structuredClone(obj) — cycles, Dates, Maps included
Map vs plain object? Any key type, insertion order, .size, no prototype collisions
Set — headline use? Dedupe: [...new Set(arr)]

BEGINNER LEVEL

1. Beginner Questions

Q1: What is React and why use it?

A JavaScript library for building user interfaces using reusable components. Key benefits: declarative UI, Virtual DOM for efficient updates, component reusability, one-way data flow, and a huge ecosystem.

Q2: What is JSX?

JavaScript XML — syntax sugar that lets you write HTML-like markup in JS. Babel compiles it to React.createElement() calls. 

const el = <h1 className="title">Hello {name}</h1>;
// compiles to:
const el = React.createElement('h1', { className: 'title' }, `Hello ${name}`);

Differences from HTML: className (not class), htmlFor, camelCase events (onClick), expressions in {}.

Q3: What is the Virtual DOM? ★ Most asked

An in-memory, lightweight copy of the real DOM. On every state change React:

  1. Creates a new virtual tree
  2. Diffs it against the previous tree (reconciliation)
  3. Applies only the minimal set of changes to the real DOM (batched)

Real DOM manipulation is slow; diffing JS objects is fast — hence the performance win.

Q4: Functional vs Class components?
Functional (modern ✅) Class (legacy)
Plain functions + hooks extends React.Component
useState / useEffect this.state / lifecycle methods
No this binding issues Requires binding handlers
Less code, easier testing Still needed for Error Boundaries
Q5: Props vs State?
  • Props — passed from parent, read-only (immutable in child)
  • State — owned and managed by the component, changes trigger re-render

Analogy: props = function arguments; state = variables declared inside the function.

Q6: Why are keys important in lists? ★

Keys let React identify which items changed, were added, or removed during diffing. Without stable keys, React re-renders incorrectly or loses input state. 

{users.map(user => <li key={user.id}>{user.name}</li>)}

// ❌ Bad: key={index} — breaks when list reorders/filters
// ✅ Good: key={user.id} — stable, unique
Q7: Controlled vs Uncontrolled components?
// Controlled — React state is the source of truth ✅
<input value={name} onChange={e => setName(e.target.value)} />

// Uncontrolled — DOM holds the value, read via ref
<input ref={inputRef} defaultValue="hello" />
Q8: Ways to render conditionally?
{isLoggedIn && <Dashboard />}                     // logical AND
{isLoggedIn ? <Dashboard /> : <Login />}          // ternary
{count === 0 ? null : <Badge count={count} />}    // render nothing

// ⚠️ Gotcha: {items.length && <List/>} renders "0" when empty!
// Fix: {items.length > 0 && <List/>}
Q9: What are Fragments?

Group children without adding extra DOM nodes:

return (
  <>
    <Header />
    <Content />
  </>
);  // <React.Fragment key={x}> when a key is needed
Q10: What is one-way data flow?

Data flows down via props; events flow up via callback props. A child never modifies parent state directly — it calls a function the parent passed down. Makes data changes predictable and debuggable.

INTERMEDIATE LEVEL

2. Intermediate Questions — Hooks Deep Dive

Q11: Explain useState. Why use functional updates?
const [count, setCount] = useState(0);

// ❌ Trap: state updates are batched + closures capture old values
const handleClick = () => {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1);
};  // count becomes 1, NOT 3!

// ✅ Functional update — always uses latest state
setCount(c => c + 1);  // ×3 → count becomes 3
Q12: Explain useEffect and its dependency array. ★ 
useEffect(() => { ... });          // runs after EVERY render
useEffect(() => { ... }, []);      // runs ONCE (on mount)
useEffect(() => { ... }, [id]);    // runs when `id` changes

// Cleanup — runs before next effect & on unmount
useEffect(() => {
  const id = setInterval(tick, 1000);
  return () => clearInterval(id);   // prevents memory leaks
}, []);
Q13: Map class lifecycle methods to hooks.
Class method Hook equivalent

Q14: What is useRef used for?
  1. DOM access: inputRef.current.focus()
  2. Mutable values that persist across renders WITHOUT re-rendering (timer IDs, previous values) 
const inputRef = useRef(null);
<input ref={inputRef} />
<button onClick={() => inputRef.current.focus()}>Focus</button>
Q15: What is prop drilling and how does Context solve it?

Passing props through many intermediate components that don't use them. Context provides values to any depth: 

const ThemeContext = createContext('light');

// Provider (top)
<ThemeContext.Provider value={theme}>
  <App />
</ThemeContext.Provider>

// Consumer (any depth)
const theme = useContext(ThemeContext);

Caveat: every consumer re-renders when the context value changes — don't put rapidly-changing state in context.

Q16: useMemo vs useCallback? ★ 
// useMemo — memoizes a computed VALUE
const sorted = useMemo(() => heavySort(items), [items]);

// useCallback — memoizes the FUNCTION reference
const handleClick = useCallback(() => setOpen(true), []);
// useCallback(fn, deps) === useMemo(() => fn, deps)

When it matters: passing callbacks to React.memo children (stable reference prevents re-render) or skipping expensive recalculations.

Q17: What does React.memo do?

A higher-order component that skips re-rendering when props are shallowly equal: 

const UserCard = React.memo(function UserCard({ user, onSelect }) {
  return <div onClick={onSelect}>{user.name}</div>;
});
// ⚠️ Only works if onSelect is stable → pair with useCallback
Q18: What are the Rules of Hooks?
  1. Only call hooks at the top level — never inside loops, conditions, or nested functions
  2. Only call hooks from React function components or custom hooks

Why: React tracks hooks by call order — conditional calls scramble the order.

Q19: Write a custom hook. ★ Common live-coding 
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    setLoading(true);
    fetch(url, { signal: controller.signal })
      .then(res => res.json())
      .then(setData)
      .catch(err => err.name !== 'AbortError' && setError(err))
      .finally(() => setLoading(false));
    return () => controller.abort();   // cancel on unmount/url change
  }, [url]);

  return { data, loading, error };
}

// Usage
const { data, loading } = useFetch('/api/users');
Q20: When do you use useReducer over useState?

When state is complex/nested or next state depends on multiple actions: 

function reducer(state, action) {
  switch (action.type) {
    case 'add':    return [...state, action.todo];
    case 'remove': return state.filter(t => t.id !== action.id);
    default:       return state;
  }
}
const [todos, dispatch] = useReducer(reducer, []);
dispatch({ type: 'add', todo: newTodo });

Q23: Explain the stale closure problem. ★ Tricky 
// ❌ Bug: count stuck at 1
useEffect(() => {
  const id = setInterval(() => {
    setCount(count + 1);   // closure captured count = 0 forever

Q25: How do you optimize React performance? ★
  • React.memo + useCallback/useMemo for expensive children
  • Code splitting with lazy/Suspense
  • Stable keys in lists; virtualize long lists (react-window)
  • Move state down (localize re-renders) or lift content up as children
  • Debounce rapid inputs; paginate large data
  • Profile with React DevTools Profiler before optimizing
Q26: How does code splitting work?
const Dashboard = lazy(() => import('./Dashboard'));

<Suspense fallback={<Spinner />}>
  <Dashboard />
</Suspense>

The Dashboard bundle downloads only when first rendered — smaller initial load.

Q27: What are Error Boundaries?

Components that catch render errors in their child tree and show a fallback UI. Must be class components (or use the react-error-boundary package). 

class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  componentDidCatch(error, info) { logService(error, info); }
  render() {
    if (this.state.hasError) return <h1>Something went wrong.</h1>;
    return this.props.children;
  }
}

Doesn't catch: event handlers, async code, SSR errors.

Q28: What's new in React 18?
  • Automatic batching — multiple setStates batched even in promises/timeouts
  • Concurrent rendering — React can pause/resume renders
  • useTransition — mark updates as non-urgent (keep typing responsive)
  • useDeferredValue, useId, Suspense improvements
  • New root API: createRoot(el).render(<App />)
Q29: CSR vs SSR vs SSG?
Strategy HTML generated Best for
CSR (plain React) In browser (JS) Dashboards, apps behind login
SSR (Next.js) Per request on server SEO + dynamic data
SSG (Next.js) At build time Blogs, marketing, docs

Hydration: attaching React event listeners to server-rendered HTML.

Q30: Why can't you update state on an unmounted component, and how do you avoid it?

It signals a memory leak (e.g., fetch resolving after unmount). Avoid with cleanup: AbortController for fetches, clearing timers/subscriptions in useEffect cleanup, or an isMounted flag/cancelled variable in the closure.

4. Practical Coding Tasks

Task 1: Todo App (the #1 live-coding question)
function TodoApp() {
  const [todos, setTodos] = useState([]);
  const [text, setText] = useState('');

  const addTodo = () => {
    if (!text.trim()) return;
    setTodos([...todos, { id: Date.now(), text, done: false }]);
    setText('');
  };

  const toggle = (id) =>
    setTodos(todos.map(t =>
      t.id === id ? { ...t, done: !t.done } : t));

  const remove = (id) =>
    setTodos(todos.filter(t => t.id !== id));

  return (
    <div>
      <input value={text}
        onChange={e => setText(e.target.value)}
        onKeyDown={e => e.key === 'Enter' && addTodo()} />
      <button onClick={addTodo}>Add</button>
      <ul>
        {todos.map(t => (
          <li key={t.id}>
            <span
              style={{ textDecoration: t.done ? 'line-through' : 'none' }}
              onClick={() => toggle(t.id)}>
              {t.text}
            </span>
            <button onClick={() => remove(t.id)}>✕</button>
          </li>
        ))}
      </ul>
    </div>
  );
}
Task 2: Debounced Search (tests useEffect mastery)
function Search() {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState([]);

  useEffect(() => {
    if (!query) { setResults([]); return; }

    const id = setTimeout(async () => {
      const res = await fetch(`/api/search?q=${query}`);
      setResults(await res.json());
    }, 500);

    return () => clearTimeout(id);  // cancels previous timer = debounce!
  }, [query]);

  return (
    <>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      <ul>{results.map(r => <li key={r.id}>{r.name}</li>)}</ul>
    </>
  );
}

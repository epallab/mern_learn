BEGINNER LEVEL

1. Beginner Questions

Q1: What is MongoDB? How is it different from SQL databases?

A NoSQL, document-oriented database that stores data as flexible, JSON-like documents (BSON) instead of rows and tables.

SQL (MySQL/Postgres) MongoDB
Tables Collections
Rows Documents
Columns Fields
Fixed schema Flexible / dynamic schema
JOINs $lookup / embedding
Scales vertically Scales horizontally (sharding)
Q2: When would you choose MongoDB over SQL?
  • Flexible/evolving schemas, rapid iteration
  • Hierarchical or nested data (naturally maps to JSON)
  • Horizontal scaling and high write throughput
  • Choose SQL instead for complex multi-table joins, strict relational integrity, heavy multi-row transactions
Q3: What is BSON?

Binary JSON — MongoDB's storage format. Supports extra types JSON lacks: ObjectId, Date, Decimal128, binary data. Faster to parse and traverse than plain JSON.

Q4: What is ObjectId and what's inside it?

The default 12-byte unique _id: 4 bytes timestamp + 5 bytes random + 3 bytes incrementing counter. Because it embeds a timestamp, sorting by _id ≈ sorting by creation time.

Q5: Show the basic CRUD operations. ★ 
// CREATE
db.users.insertOne({ name: 'Alice', age: 25 });
db.users.insertMany([{ name: 'Bob' }, { name: 'Carol' }]);

// READ
db.users.find({ age: { $gte: 18 } });        // all matches (cursor)
db.users.findOne({ email: 'a@b.com' });      // first match

// UPDATE
db.users.updateOne({ name: 'Alice' }, { $set: { age: 26 } });
db.users.updateMany({}, { $inc: { visits: 1 } });

// DELETE
db.users.deleteOne({ _id: someId });
db.users.deleteMany({ inactive: true });
Q6: Common query operators?
db.products.find({ price: { $gte: 10, $lte: 50 } });      // range
db.users.find({ role: { $in: ['admin', 'editor'] } });     // in list
db.users.find({ $or: [{ age: { $lt: 18 } }, { banned: true }] });
db.users.find({ name: { $regex: /^ali/i } });               // regex
db.users.find({ phone: { $exists: true } });                // field exists
db.users.find({ tags: { $all: ['js', 'db'] } });            // array contains all
Q7: Common update operators?
{ $set: { name: 'Bob' } }        // set/create field
{ $unset: { temp: '' } }          // remove field
{ $inc: { stock: -1 } }           // increment/decrement
{ $push: { tags: 'new' } }        // append to array
{ $pull: { tags: 'old' } }        // remove from array
{ $addToSet: { tags: 'x' } }      // push only if not present
Q8: What is Mongoose and why use it?

An ODM (Object Data Modeling) library for Node.js. Adds what raw MongoDB lacks: schemas, validation, type casting, middleware hooks, population (pseudo-joins), and a cleaner query API.

Q9: find() vs findOne() return types?

find() returns a cursor (array-like, iterable); findOne() returns a single document or null. In Mongoose, both return thenable Query objects you can await.

Q10: Sort, limit, skip, and projection?
db.users.find(
  { age: { $gte: 18 } },          // filter
  { name: 1, email: 1, _id: 0 }   // projection (only these fields)
)
.sort({ age: -1 })                 // -1 desc, 1 asc
.skip(20)
.limit(10);
INTERMEDIATE LEVEL

2. Intermediate Questions

Q11: Explain the aggregation pipeline. ★ Most asked

A framework for data processing: documents flow through stages, each transforming the results — like a Unix pipe. 

// "Top 5 customers by total spend on delivered orders"
db.orders.aggregate([
  { $match: { status: 'delivered' } },            // 1. filter early
  { $group: {                                     // 2. group + compute
      _id: '$customerId',
      total: { $sum: '$amount' },
      orders: { $sum: 1 }
  }},
  { $sort: { total: -1 } },                       // 3. sort
  { $limit: 5 },                                  // 4. take top 5
  { $project: {                                   // 5. reshape output
      customerId: '$_id', total: 1, orders: 1, _id: 0
  }}
]);

Key stages: $match, $group, $project, $sort, $limit, $skip, $lookup, $unwind, $count, $addFields.

Q12: How do you do JOINs in MongoDB ($lookup)?
db.orders.aggregate([
  { $lookup: {
      from: 'users',            // collection to join
      localField: 'userId',     // field in orders
      foreignField: '_id',      // field in users
      as: 'customer'            // output array field
  }},
  { $unwind: '$customer' }      // array → object
]);
Q13: What is $unwind?

Deconstructs an array field — outputs one document per array element. Essential for grouping/aggregating on array contents.

Q14: Explain indexes. Types and tradeoffs. ★

B-tree structures that make queries fast by avoiding full collection scans. Tradeoff: slower writes + extra storage/RAM. 

db.users.createIndex({ email: 1 }, { unique: true });      // single + unique
db.products.createIndex({ category: 1, price: -1 });        // compound
db.articles.createIndex({ title: 'text', body: 'text' });   // text search
db.sessions.createIndex({ createdAt: 1 },
  { expireAfterSeconds: 3600 });                             // TTL (auto-delete)

Compound index rule: supports queries on prefixes — index {a:1, b:1} helps queries on {a} and {a,b}, but NOT on {b} alone.

Q15: How do you check if a query uses an index?
db.users.find({ email: 'x@y.com' }).explain('executionStats');
// Look for:
// 'IXSCAN'    → index used ✅
// 'COLLSCAN'  → full collection scan ❌
// totalDocsExamined vs nReturned → efficiency ratio
Q16: Embedding vs Referencing — how do you decide? ★
Embed when... Reference when...
Data is read together Data is shared across documents
"Contains" relationship (1:few) 1:many or many:many
Sub-data rarely changes Sub-data updates independently
Bounded size (user + addresses) Unbounded growth (posts + comments)

Rule of thumb: "Data that is accessed together should be stored together" — but never let a document grow unbounded (16MB limit).

Q17: Write a Mongoose schema with validation and hooks.
const userSchema = new mongoose.Schema({
  email: {
    type: String, required: true,
    unique: true, lowercase: true, trim: true
  },
  password: { type: String, required: true, minlength: 8, select: false },
  age: { type: Number, min: 18, max: 100 },
  role: { type: String, enum: ['user', 'admin'], default: 'user' }
}, { timestamps: true });   // auto createdAt / updatedAt

// Pre-save hook — hash password
userSchema.pre('save', async function () {
  if (this.isModified('password'))
    this.password = await bcrypt.hash(this.password, 12);
});

const User = mongoose.model('User', userSchema);
Q18: What is populate()?

Mongoose's pseudo-join: replaces an ObjectId reference with the actual document. 

const postSchema = new mongoose.Schema({
  title: String,
  author: { type: mongoose.Schema.Types.ObjectId, ref: 'User' }
});

const posts = await Post.find()
  .populate('author', 'name email');   // only these fields
Q19: Offset vs cursor-based pagination?
// Offset (skip/limit) — simple, but slow on deep pages
Product.find().skip((page - 1) * 20).limit(20);

// Cursor-based — fast at any depth (uses index on _id)
Product.find({ _id: { $gt: lastSeenId } }).limit(20);

skip(100000) still walks 100k docs — cursor-based jumps straight via the index.

Q20: What do the options in findOneAndUpdate mean?
await User.findOneAndUpdate(
  { email: 'a@b.com' },
  { $set: { name: 'Alice' } },
  {
    new: true,              // return the UPDATED doc (default: old one!)
    upsert: true,           // insert if not found
    runValidators: true     // apply schema validation on update
  }
);
ADVANCED LEVEL

3. Advanced Questions

Q21: What is replication? How does a replica set work? ★

A replica set = one primary (receives all writes) + multiple secondaries (replicate the primary's oplog). Purpose: high availability and data redundancy.

  • If the primary fails, secondaries hold an election and promote a new primary (automatic failover)
  • Minimum recommended: 3 nodes (or 2 + arbiter) for majority voting
  • Secondaries can serve reads (readPreference: 'secondary') — eventual consistency tradeoff
Q22: What is sharding? What makes a good shard key?

Horizontal partitioning of data across multiple servers (shards) for scaling beyond one machine. A mongos router directs queries; config servers hold metadata.

Good shard key: high cardinality, evenly distributed writes, matches common query patterns. Bad: monotonically increasing keys (like timestamps) — all writes hit one shard ("hot shard").

Replication Sharding
Purpose Availability / redundancy Scalability / capacity
Data Full copy on each node Split across nodes
Q23: Does MongoDB support transactions?

Yes — single-document operations are always atomic; multi-document ACID transactions since v4.0 (replica sets) / v4.2 (sharded). 

const session = await mongoose.startSession();
session.startTransaction();
try {
  await Account.updateOne({ _id: from },
    { $inc: { balance: -100 } }, { session });
  await Account.updateOne({ _id: to },
    { $inc: { balance: 100 } }, { session });
  await session.commitTransaction();
} catch (err) {
  await session.abortTransaction();
  throw err;
} finally {
  session.endSession();
}

Note: good schema design (embedding) often removes the need for transactions.

Q24: What are read and write concerns?
  • Write concern — w: 1 (primary ack), w: 'majority' (majority of nodes — durable), w: 0 (fire-and-forget)
  • Read concern — local (default), majority (no rollback risk), linearizable
  • Tradeoff: stronger guarantees = higher latency

Q26: What are change streams?

Real-time subscriptions to data changes (insert/update/delete) — like triggers. Built on the oplog; requires a replica set. 

const stream = Order.watch();
stream.on('change', (change) => {
  io.emit('orderUpdate', change.fullDocument);  // push to clients
});
Q27: How do you optimize a slow MongoDB query?
  1. Run .explain('executionStats') — look for COLLSCAN
  2. Add appropriate indexes (match query + sort fields)
  3. Use projection — fetch only needed fields
  4. In aggregations: $match and $project as early as possible
  5. Use .lean() in Mongoose (plain objects, ~5x faster reads)
  6. Check the profiler: db.setProfilingLevel(1, { slowms: 100 })
Q28: Name common schema design patterns.
  • Subset pattern — embed only the most-accessed items (top 10 reviews), reference the rest
  • Bucket pattern — group time-series data into hourly/daily docs
  • Computed pattern — store precomputed totals/averages on write
  • Extended reference — duplicate a few frequently-needed fields (name, thumbnail) alongside the ObjectId

Task 2: Average order value per month (aggregation)
db.orders.aggregate([
  { $group: {
      _id: {
        year: { $year: '$createdAt' },
        month: { $month: '$createdAt' }
      },
      avgOrder: { $avg: '$amount' },
      revenue: { $sum: '$amount' }
  }},
  { $sort: { '_id.year': 1, '_id.month': 1 } }
]);
Task 3: Find duplicate emails
db.users.aggregate([
  { $group: { _id: '$email', count: { $sum: 1 } } },
  { $match: { count: { $gt: 1 } } }

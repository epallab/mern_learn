BEGINNER LEVEL

1. Beginner Questions

Q1: What is Express.js and why use it over plain Node.js?

A minimal, unopinionated web framework for Node.js. Plain Node's http module requires manual URL parsing, routing, and body handling — Express provides routing, middleware, request parsing, and a cleaner API out of the box.

Q2: How do you create a basic Express server?
const express = require('express');
const app = express();

app.get('/', (req, res) => res.send('Hello World'));

app.listen(3000, () => console.log('Server on port 3000'));
Q3: What is middleware? ★ Most asked

Functions with access to req, res, and next that execute during the request-response cycle. They can modify request/response objects, end the cycle, or pass control via next(). 

app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`);
  next(); // without this, the request hangs!
});
Q4: app.get() vs app.use()?
  • app.get('/path') — matches GET requests to the exact path
  • app.use('/path') — matches all methods and any path starting with /path
Q5: Route params vs query params?
// GET /users/42?sort=name&page=2
app.get('/users/:id', (req, res) => {
  req.params.id;    // '42'
  req.query.sort;   // 'name'
  req.query.page;   // '2'
});
Q6: What do express.json() and express.urlencoded() do?
  • express.json() — parses JSON request bodies into req.body
  • express.urlencoded({ extended: true }) — parses HTML form data

Without them, req.body is undefined.

Q7: How do you serve static files?
app.use(express.static('public'));
// Now /public/logo.png is served at /logo.png

app.use('/assets', express.static('public')); // with URL prefix
Q8: res.send() vs res.json() vs res.end()?
  • res.send() — sends any type, auto-sets Content-Type
  • res.json() — converts to JSON, sets application/json
  • res.end() — ends response without data
Q9: Essential HTTP status codes?
Code Meaning Use case
200 OK Successful GET/PUT
201 Created Successful POST
204 No Content Successful DELETE
400 Bad Request Validation failure
401 Unauthorized Missing/invalid token
403 Forbidden Valid token, no permission
404 Not Found Resource doesn't exist
500 Server Error Unhandled exception
Q10: How do you handle a 404 route?
// Placed AFTER all other routes
app.use((req, res) => {
  res.status(404).json({ error: 'Route not found' });
});
INTERMEDIATE LEVEL

2. Intermediate Questions

Q11: Name the 5 types of middleware. ★ 
// 1. Application-level
app.use(logger);

// 2. Router-level
router.use(authCheck);

// 3. Error-handling (MUST have 4 params)
app.use((err, req, res, next) => {
  res.status(500).json({ error: err.message });
});

// 4. Built-in
app.use(express.json());
app.use(express.static('public'));

// 5. Third-party
app.use(cors());
app.use(helmet());
Q12: How does error-handling middleware work?

Identified by having exactly 4 parameters (err, req, res, next). Express skips to it whenever next(err) is called or a synchronous error is thrown. It must be registered after all routes.

Q13: What is express.Router()?

A mini, mountable route handler for organizing routes into modules.

// routes/users.js
const router = require('express').Router();
router.get('/', getAllUsers);
router.post('/', createUser);
module.exports = router;

// server.js
app.use('/api/users', require('./routes/users'));
Q14: What are the variants of next()?
  • next() — pass to the next middleware
  • next(err) — skip everything, jump to error handler
  • next('route') — skip remaining handlers in the current route
  • Not calling it (and not responding) — request hangs forever
Q15: How do you handle CORS?
const cors = require('cors');

app.use(cors({
  origin: 'https://myapp.com',   // allowed origin
  methods: ['GET', 'POST', 'PUT', 'DELETE'],
  credentials: true               // allow cookies
}));

Why it exists: browsers block cross-origin requests by default; the server must explicitly allow them via headers like Access-Control-Allow-Origin.

Q16: How do you handle file uploads?
const multer = require('multer');
const upload = multer({
  dest: 'uploads/',
  limits: { fileSize: 5 * 1024 * 1024 }  // 5MB
});

app.post('/upload', upload.single('avatar'), (req, res) => {
  res.json({ file: req.file });
});
Q17: Implement JWT authentication middleware. ★ 
const jwt = require('jsonwebtoken');

const auth = (req, res, next) => {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ message: 'No token' });

  try {
    req.user = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch {
    res.status(401).json({ message: 'Invalid token' });
  }
};

// Usage
app.get('/api/profile', auth, (req, res) => {
  res.json({ user: req.user });
});
Q18: How do you structure a production Express app?
project/
├── config/          # DB connection, env setup
├── controllers/     # Request handlers (business logic)
├── models/          # Mongoose schemas
├── routes/          # Route definitions
├── middleware/      # Auth, validation, error handlers
├── utils/           # Helpers, custom errors
├── app.js           # Express app setup
└── server.js        # Entry point (listen, DB connect)

Separating app.js from server.js makes the app testable without starting a server.

Q19: Does middleware order matter?

Yes — critically. Middleware executes top-to-bottom. Common bug: defining routes before express.json() means req.body is undefined. Error handlers and 404 handlers must come last.

Q20: Important req object properties?

req.ip Client IP address
req.method / req.path HTTP method / URL path
ADVANCED LEVEL

3. Advanced Questions

Q21: How do you handle async errors in Express? ★ Tricky

In Express 4, rejected promises in route handlers are NOT caught automatically — the request hangs. Solutions: 

// Option 1: try/catch in every handler (verbose)
app.get('/users', async (req, res, next) => {
  try {
    res.json(await User.find());
  } catch (err) { next(err); }
});

// Option 2: asyncHandler wrapper (clean) ✅
const asyncHandler = (fn) => (req, res, next) =>
  Promise.resolve(fn(req, res, next)).catch(next);

app.get('/users', asyncHandler(async (req, res) => {
  res.json(await User.find());
}));

// Option 3: Express 5 handles rejected promises natively
Q22: Build a centralized error handler with custom errors. 
// utils/AppError.js
class AppError extends Error {
  constructor(message, statusCode) {
    super(message);
    this.statusCode = statusCode;
    this.isOperational = true;
  }
}

// middleware/errorHandler.js
const errorHandler = (err, req, res, next) => {
  const status = err.statusCode || 500;
  res.status(status).json({
    status: 'error',
    message: err.isOperational ? err.message : 'Something went wrong'
  });
};

// Usage in a controller
if (!user) return next(new AppError('User not found', 404));
Q23: Express security best practices?
  • helmet() — sets secure HTTP headers
  • express-rate-limit — prevents brute-force attacks
  • express-mongo-sanitize — blocks NoSQL injection ({"$gt": ""})
  • Validate input with joi / express-validator
  • Limit body size: express.json({ limit: '10kb' })
  • Use HTTPS, httpOnly cookies, and CSRF protection
  • Hide X-Powered-By: app.disable('x-powered-by')
Q24: How do you improve Express performance?
  • compression() — gzip responses
  • Enable caching headers / Redis for repeated queries
  • Use clustering or PM2 to utilize all CPU cores
  • Set NODE_ENV=production (up to 3x faster — disables dev overhead)
  • Use lean queries (Model.find().lean()) and pagination
  • Avoid synchronous code in handlers
Q25: JWT vs Sessions in Express?
JWT Sessions (express-session)
State Stateless (client-side) Stateful (server-side)
Scaling Easy — no shared store Needs Redis for multiple servers
Revocation Hard until expiry Instant (destroy session)
Best for APIs, mobile, microservices Server-rendered web apps
Q26: How do you test Express apps?
const request = require('supertest');
const app = require('../app');

describe('GET /api/users', () => {
  it('returns 200 and an array', async () => {
    const res = await request(app).get('/api/users');
    expect(res.statusCode).toBe(200);
    expect(Array.isArray(res.body)).toBe(true);
  });

  it('returns 401 without token', async () => {
    const res = await request(app).get('/api/profile');
    expect(res.statusCode).toBe(401);
  });
});
Q27: How do you implement API versioning?
app.use('/api/v1/users', v1UserRoutes);
app.use('/api/v2/users', v2UserRoutes);

Alternatives: version via headers (Accept-Version) or query params. URL versioning is most common and cache-friendly.

Q28: What is app.all() and how does it differ from app.use()?
  • app.all('/path') — all HTTP methods, exact path match, supports route patterns
  • app.use('/path') — all methods, prefix match (matches /path/anything)
Q29: What does app.set('trust proxy', true) do?

Tells Express it's behind a reverse proxy (nginx, load balancer), so req.ip and req.protocol reflect the real client via X-Forwarded-* headers. Required for correct rate limiting and secure cookies in production.

Q30: How do you stream a response?
app.get('/download', (req, res) => {
  res.setHeader('Content-Type', 'video/mp4');
  fs.createReadStream('large-video.mp4').pipe(res);
});

4. Practical Coding Task — Complete CRUD API

The most common live-coding request. Be able to write this from scratch: 

const express = require('express');
const app = express();
app.use(express.json());

let users = [{ id: 1, name: 'Alice' }];
let nextId = 2;

// READ all (with pagination)
app.get('/api/users', (req, res) => {
  const { page = 1, limit = 10 } = req.query;
  const start = (page - 1) * limit;
  res.json(users.slice(start, start + Number(limit)));
});

// READ one
app.get('/api/users/:id', (req, res) => {
  const user = users.find(u => u.id === Number(req.params.id));
  if (!user) return res.status(404).json({ error: 'Not found' });
  res.json(user);
});

// CREATE
app.post('/api/users', (req, res) => {
  const { name } = req.body;
  if (!name) return res.status(400).json({ error: 'Name required' });
  const user = { id: nextId++, name };
  users.push(user);
  res.status(201).json(user);
});

// UPDATE
app.put('/api/users/:id', (req, res) => {
  const user = users.find(u => u.id === Number(req.params.id));
  if (!user) return res.status(404).json({ error: 'Not found' });
  user.name = req.body.name ?? user.name;
  res.json(user);
});

// DELETE
app.delete('/api/users/:id', (req, res) => {
  const index = users.findIndex(u => u.id === Number(req.params.id));
  if (index === -1) return res.status(404).json({ error: 'Not found' });
  users.splice(index, 1);
  res.status(204).end();
});

// 404 + error handlers (always last)
app.use((req, res) => res.status(404).json({ error: 'Route not found' }));
app.use((err, req, res, next) => {
  res.status(500).json({ error: 'Server error' });
});

app.listen(3000);

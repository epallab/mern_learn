BEGINNER LEVEL

1. Beginner Questions

Q1: What is Node.js?

A JavaScript runtime environment built on Chrome's V8 engine that executes JS outside the browser. It uses an event-driven, non-blocking I/O model, making it ideal for scalable network applications.

Q2: How is Node.js different from browser JavaScript?
  • No DOM/window; instead has global, process, Buffer
  • Access to file system, network, OS
  • Module systems (CommonJS/ESM) built-in
  • No browser security sandbox
Q3: Is Node.js single-threaded?

The event loop is single-threaded, but Node uses the libuv thread pool (default 4 threads) behind the scenes for file I/O, DNS, and crypto operations. So: single-threaded JS execution, multi-threaded under the hood.

Q4: package.json vs package-lock.json?
  • package.json — project metadata, dependency ranges (^4.18.0)
  • package-lock.json — exact versions of the entire dependency tree, ensuring identical installs across machines
Q5: dependencies vs devDependencies?
  • dependencies — needed at runtime (express, mongoose)
  • devDependencies — development only (nodemon, jest, eslint)
Q6: CommonJS vs ES Modules?
// CommonJS — synchronous, dynamic
const fs = require('fs');
module.exports = { myFunc };

// ES Modules — asynchronous, static, tree-shakeable
import fs from 'fs';
export default myFunc;
Q7: What is callback hell and how do you avoid it?

Deeply nested callbacks that become unreadable. Solutions: Promises, async/await, modularizing functions.

Q8: What are __dirname and __filename?

__dirname = absolute path of the current directory; __filename = absolute path of the current file. (Not available in ES modules — use import.meta.url instead.)

Q9: Synchronous vs asynchronous fs methods?
const data = fs.readFileSync('file.txt');        // blocks event loop ❌
fs.readFile('file.txt', (err, data) => {...});   // non-blocking ✅
const data = await fs.promises.readFile('file.txt'); // modern ✅
Q10: What is REPL?

Read-Eval-Print-Loop — the interactive shell you get by typing node in the terminal.

INTERMEDIATE LEVEL

2. Intermediate Questions

Q11: Explain the Event Loop phases. ★ Most asked

The event loop cycles through these phases:

  1. Timers — executes setTimeout / setInterval callbacks
  2. Pending callbacks — deferred I/O callbacks
  3. Idle/prepare — internal use
  4. Poll — retrieves new I/O events; executes I/O callbacks
  5. Check — executes setImmediate callbacks
  6. Close callbacks — e.g., socket.on('close')

Between every phase, Node drains microtask queues: first the process.nextTick queue, then the Promise queue.

Q12: process.nextTick() vs setImmediate() vs setTimeout(fn, 0)? 
setTimeout(() => console.log('timeout'), 0);
setImmediate(() => console.log('immediate'));
process.nextTick(() => console.log('nextTick'));
Promise.resolve().then(() => console.log('promise'));
console.log('sync');

// Output: sync → nextTick → promise → timeout/immediate
  • nextTick — highest priority, fires before promises
  • Inside an I/O callback, setImmediate always beats setTimeout
  • In the main module, timeout vs immediate order is non-deterministic
Q13: What is the EventEmitter?

The core of Node's event-driven architecture. Most core modules (http, streams) extend it. 

const EventEmitter = require('events');

class OrderService extends EventEmitter {}
const orders = new OrderService();

orders.on('placed', (id) => console.log(`Order ${id} placed`));
orders.once('placed', (id) => sendEmail(id));  // fires only once
orders.emit('placed', 42);
Q14: What are Streams? Name the types.

Interfaces for processing data in chunks instead of loading it all in memory.

  • Readable — fs.createReadStream
  • Writable — fs.createWriteStream
  • Duplex — both (TCP sockets)
  • Transform — modify while passing through (zlib compression) 
// Serve a 2GB file using ~64KB of memory
fs.createReadStream('huge-video.mp4').pipe(res);
Q15: What is a Buffer?

A fixed-size chunk of raw binary data outside V8's heap. Used for TCP streams, file operations, binary protocols. 

const buf = Buffer.from('Hello');
console.log(buf);            // <Buffer 48 65 6c 6c 6f>
console.log(buf.toString()); // 'Hello'
Q16: spawn() vs exec() vs fork()?
Method Use case
spawn Long-running process, streams output (large data)
exec Short commands, buffers entire output in memory
fork Spawns a new Node process with built-in IPC channel
Q17: How do you handle errors in async code?
// async/await — try/catch
try {
  const user = await User.findById(id);
} catch (err) {
  next(err);
}

// Global safety nets (log + graceful shutdown)
process.on('unhandledRejection', (err) => { ... });
process.on('uncaughtException', (err) => { process.exit(1); });
Q18: What is middleware in Node.js?

Functions in the request pipeline that can inspect/modify req/res and pass control via next(). Core to Express architecture.

Q19: How do environment variables work?
require('dotenv').config();
const port = process.env.PORT || 3000;

Never commit .env files — use them for secrets, API keys, DB URIs.

Q20: What is libuv?

The C library that gives Node its event loop and async I/O. It manages the thread pool, handles OS-level differences, and delegates heavy operations off the main thread.

ADVANCED LEVEL

3. Advanced Questions

Q21: Cluster vs Worker Threads vs Child Processes? ★
Cluster Worker Threads Child Process
Memory Separate Shared possible Separate
Best for Scaling HTTP servers CPU-heavy tasks External programs
Communication IPC Messages / shared memory IPC / stdio 
// Cluster — one worker per core
const cluster = require('cluster');
const os = require('os');

if (cluster.isPrimary) {
  os.cpus().forEach(() => cluster.fork());
  cluster.on('exit', () => cluster.fork()); // auto-restart
} else {
  require('./server');
}
Q22: How do you detect and prevent memory leaks?

Common causes: global variables, forgotten timers/listeners, closures holding large references, unbounded caches.

Detection: process.memoryUsage(), Chrome DevTools heap snapshots (node --inspect), clinic.js.

Prevention: remove listeners (emitter.off), clear intervals, use WeakMap, cap cache sizes (LRU).

Q23: What is backpressure in streams?

When a writable stream can't consume data as fast as the readable produces it. pipe() handles it automatically; manually, write() returns false → pause until the 'drain' event.

Q24: How do you implement graceful shutdown?
process.on('SIGTERM', () => {
  server.close(async () => {        // stop accepting new requests
    await mongoose.disconnect();     // close DB connections
    process.exit(0);
  });
  setTimeout(() => process.exit(1), 10000); // force-kill fallback
});
Q25: How would you avoid blocking the event loop?
  • Never use sync methods (fs.readFileSync, crypto.pbkdf2Sync) in servers
  • Offload CPU work to worker threads
  • Break large loops with setImmediate chunks
  • Use streaming instead of loading full payloads
Q26: Node.js security best practices?
  • Validate/sanitize all input (prevent injection)
  • helmet for security headers, rate limiting (express-rate-limit)
  • Avoid eval(); keep dependencies audited (npm audit)
  • Store secrets in env vars; hash passwords with bcrypt
  • Run with least privilege; set request size limits
Q27: How does V8 garbage collection work?

Generational GC: new space (short-lived objects, fast Scavenge collection) and old space (survivors, Mark-Sweep-Compact). Long GC pauses hint at memory pressure.

Q28: REST vs GraphQL in a Node backend?

REST: simple, cacheable, standard. GraphQL: single endpoint, client specifies exact fields (no over/under-fetching), but adds complexity in caching and rate limiting.

5. Practical Coding Tasks

Task 1: HTTP server without Express
const http = require('http');

const server = http.createServer((req, res) => {
  if (req.url === '/api/users' && req.method === 'GET') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify([{ id: 1, name: 'Alice' }]));
  } else {
    res.writeHead(404);
    res.end(JSON.stringify({ error: 'Not found' }));
  }
});

server.listen(3000, () => console.log('Running on 3000'));
Task 2: Read POST body without Express
let body = '';
req.on('data', chunk => body += chunk);
req.on('end', () => {
  const data = JSON.parse(body);
  // process data
});

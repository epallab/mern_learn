Values & Types

Everything in JavaScript is either a small immutable value or a reference to an object. Most "weird JS" is coercion between the two.

Primitives vs references

The seven primitives (string, number, bigint, boolean, undefined, symbol, null) are copied by value. Everything else — objects, arrays, functions — is handled by reference: the variable holds a pointer, and copying the variable copies the pointer. 

let a = { count: 0 };
let b = a;          // same object, two names
b.count++;
a.count;            // 1 — a saw it

let x = 0;
let y = x;          // independent copy
y++;
x;                  // 0
This one fact explains React's rules: state must be replaced, not mutated, because change detection compares references, not contents.

Dynamic typing and typeof

Variables are untyped; values are typed. typeof reports the value's type — with two famous quirks worth memorizing: typeof null === "object" (a fossilized bug) and arrays reporting "object" (use Array.isArray). 

typeof "hi"     // "string"
typeof null     // "object"  ← the trap
typeof []       // "object"  ← use Array.isArray([])
typeof (() => {}) // "function"
"How do you check if something is an array?" is a warm-up filter question — answer instantly.

Coercion: the three targets

JavaScript converts values to exactly three targets — string, number, or boolean — depending on the operation. + prefers strings if either side is one; every other math operator forces numbers; if/!/&& force booleans. 

1 + "2"    // "12"   (+ saw a string)
"5" - 2    // 3      (- is numeric only)
"5" * "2"  // 10
+"42"      // 42     (unary + = quick number conversion)
!!""       // false  (double-bang = quick boolean)
Output-prediction rounds lean on these. Narrate the target type: "minus forces numbers, so…"

== vs === in practice

=== never converts — use it by default. == runs the coercion algorithm; its one genuinely useful behavior is that x == null is true for null and undefined, which makes a tidy "is missing" check. 

if (value == null) { /* null or undefined, nothing else */ }
0 == ""    // true — why you avoid == everywhere else
0 === ""   // false
Saying "I use === except the deliberate x == null idiom" signals you know the rule and the exception.

Truthiness as a tool

Exactly eight values are falsy: false, 0, -0, 0n, "", null, undefined, NaN. Everything else — including "0", [], {} — is truthy. Short-circuit operators return the deciding value, not a boolean, which powers common idioms: 

const name = input && input.trim();   // guard then use
const port = env.PORT || 3000;        // fallback (careful: 0 falls through!)
const port2 = env.PORT ?? 3000;       // fallback only for null/undefined
The || vs ?? distinction (0 and "" are valid values!) is a favorite senior-screen question.

Numbers: one type, sharp edges

All numbers are 64-bit floats — there is no integer type. Binary fractions can't represent 0.1 exactly, integers are only safe to 2⁵³−1, and NaN is the only value not equal to itself. 

0.1 + 0.2 === 0.3                       // false
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON // the right comparison
Number.isNaN(value)                     // the right NaN check
9007199254740993n                       // BigInt when you exceed safe ints
"Why is 0.1 + 0.2 !== 0.3?" — answer: binary floating point, and name EPSILON. Two sentences, done.

Scope & Closures

Where a variable is visible is decided by where the code is written, not where it runs. Closures fall out of that rule.

Lexical scope and blocks

Scopes nest: inner code sees outer variables, never the reverse. let/const respect any {} block; var only respects function boundaries — it leaks out of if-blocks and loops. 

function demo() {
  if (true) {
    var leaky = 1;
    let contained = 2;
  }
  leaky;      // 1 — var ignored the block
  contained;  // ReferenceError
}

Hoisting and the temporal dead zone

Declarations are registered before any code runs. Function declarations hoist whole (callable early). var hoists and initializes to undefined. let/const hoist but stay uninitialized — touching them before their line is the temporal dead zone error. 

works();                 // fine — declaration hoisted whole
function works() {}

console.log(v);          // undefined
var v = 1;

console.log(l);          // ReferenceError: TDZ
let l = 2;
Hoisting output questions open most JS interviews — predict all three cases above without hesitating.

Closures: functions carry their birthplace

A function keeps live access to the scope where it was defined, even after that scope's function has returned. The scope isn't copied — it's kept alive and shared by every function born in it. 

function bankAccount(balance) {
  return {
    deposit: (n) => (balance += n),
    view: () => balance,      // both share the same `balance`
  };
}
const acct = bankAccount(100);
acct.deposit(50);
acct.view(); // 150 — balance lives on, invisible from outside
"What is a closure?" wants three beats: definition, the still-alive-after-return part, and a real use (private state, debounce).

Closure patterns you'll actually write

// memoize — cache lives in the closure
function memoize(fn) {
  const cache = new Map();
  return (arg) => {
    if (!cache.has(arg)) cache.set(arg, fn(arg));
    return cache.get(arg);
  };
}

// once — flag lives in the closure
function once(fn) {
  let done = false, result;
  return (...args) => (done ? result : ((done = true), (result = fn(...args))));
}
memoize, once, debounce, and throttle are the four closure factories interviews ask you to write — all four are in the Practice section.

The loop trap

One var per function means every async callback in a loop shares the same, final value. let fixes it by creating a fresh binding per iteration. 

for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 0 1 2
Asked verbatim, constantly. Explain why: one shared binding vs one per iteration.

Functions & this

Functions are values. The only genuinely tricky part is this — and it follows four mechanical rules.

Declaration, expression, arrow

function decl() {}            // hoisted whole; has its own this
const expr = function () {};  // not callable before this line
const arrow = () => {};       // no own this/arguments; lexical instead

Arrows are for callbacks and anywhere you want the surrounding this. Declarations/expressions are for methods and constructors.

Default and rest parameters

function paginate(items, { page = 1, size = 20 } = {}) {
  return items.slice((page - 1) * size, page * size);
}
function sum(...nums) {                  // real array, unlike `arguments`
  return nums.reduce((a, b) => a + b, 0);
}

Defaults fire on undefined only — passing null keeps null. The = {} on the options object lets callers omit it entirely.

this: the four rules, in precedence order

  1. new Fn() → the newly created object
  2. fn.call(obj) / bind → obj, explicitly
  3. obj.fn() → the thing before the dot
  4. fn() → undefined (strict) / global (sloppy)

Ask "how is it called?", never "where is it defined?" — except arrows, which ignore all four and use the scope they were written in.

Interviewers extract a method (const f = obj.method) and ask what f() logs. Rule 4 — the object is gone.

call, apply, bind

fn.call(ctx, a, b);      // now, args listed
fn.apply(ctx, [a, b]);   // now, args as array
const tied = fn.bind(ctx, a);  // later; also pre-fills args (partial application)

bind's product is permanently tied — a later call/bind can't re-point it. That's how React class components pinned handlers: this.onClick = this.onClick.bind(this).

Arrows and this, in real code

const poller = {
  count: 0,
  start() {
    setInterval(() => {
      this.count++;            // arrow: this is still poller ✓
    }, 1000);
  },
};

With function () {} inside setInterval, this would be undefined/global. Flip side: arrows make bad object methods — { name: "x", get: () => this.name } never sees the object.

Higher-order functions and composition

Functions that take or return functions are the language's main abstraction tool — array methods, middleware, React hooks are all this shape. 

const pipe = (...fns) => (x) => fns.reduce((acc, f) => f(acc), x);
const slugify = pipe(
  (s) => s.trim().toLowerCase(),
  (s) => s.replace(/[^a-z0-9]+/g, "-"),
  (s) => s.replace(/^-|-$/g, "")
);
slugify("  Hello, World! "); // "hello-world"
Implementing pipe/compose with reduce is a frequent quick coding exercise — one line each, worth memorizing.

Objects & Prototypes

Objects are bags of properties plus a hidden link to another object. That link is the whole inheritance story.

Literals: shorthand, computed keys, methods

const type = "admin";
const user = {
  name,                       // shorthand for name: name
  [`is_${type}`]: true,       // computed key → is_admin
  greet() { return `Hi ${this.name}`; },  // method shorthand
};

Getters, setters, descriptors

const temp = {
  celsius: 20,
  get fahrenheit() { return this.celsius * 1.8 + 32; },
  set fahrenheit(f) { this.celsius = (f - 32) / 1.8; },
};
temp.fahrenheit;       // 68 — computed on read
Object.defineProperty(obj, "id", { writable: false }); // lock a property

Every property has a descriptor (writable, enumerable, configurable). You rarely write them directly, but they explain why some properties don't show in loops or refuse assignment.

The prototype chain

Reading a missing property walks the object's [[Prototype]] link upward until found or null. Writing never walks — it sets on the object itself. Methods exist once on the prototype and are shared by every instance. 

const proto = { describe() { return `${this.kind}`; } };
const dog = Object.create(proto);
dog.kind = "dog";
dog.describe(); // "dog" — found one link up, this = dog
"Where does arr.map live?" — on Array.prototype, once. Chain: arr → Array.prototype → Object.prototype → null.

Classes, modern shape

class Cache {
  static instances = 0;      // on the class itself
  #store = new Map();        // truly private per instance
  constructor(ttl) {
    this.ttl = ttl;
    Cache.instances++;
  }
  get size() { return this.#store.size; }
  set(k, v) { this.#store.set(k, { v, at: Date.now() }); }
}

Same prototype machinery underneath — plus strict mode, mandatory new, static members, and enforced #private fields.

Inheritance and super

class HttpError extends Error {
  constructor(status, message) {
    super(message);           // must run before touching `this`
    this.status = status;
    this.name = "HttpError";
  }
}
throw new HttpError(404, "Not found");

Subclassing Error is the one inheritance every backend actually uses — typed errors your Express error middleware can switch on.

"Composition over inheritance" is the expected follow-up opinion: deep class trees are rare in JS; prefer mixing behaviors via functions.

Symbols and the iterator protocol

const range = {
  from: 1, to: 3,
  *[Symbol.iterator]() {
    for (let n = this.from; n <= this.to; n++) yield n;
  },
};
[...range];           // [1, 2, 3] — spread, for..of, destructuring all work

Symbols are collision-proof keys; the well-known ones (Symbol.iterator) are how your objects plug into language syntax.

Arrays & Iteration

Ninety percent of application code is reshaping arrays. Fluency here is visible within minutes in a live-coding round.

The big three: map, filter, reduce

const names  = users.map((u) => u.name);            // transform 1:1
const active = users.filter((u) => !u.disabled);    // keep some
const total  = items.reduce((sum, i) => sum + i.price, 0); // fold to one

const byRole = users.reduce((acc, u) => {           // reduce as groupBy
  (acc[u.role] ||= []).push(u);
  return acc;
}, {});
Chained map/filter/reduce over a sample dataset is the screening question at many companies. Type these without thinking.

Search and test: find, some, every, includes

users.find((u) => u.id === id);      // first match or undefined
users.some((u) => u.isAdmin);        // at least one?
users.every((u) => u.verified);      // all?
tags.includes("urgent");             // membership (===, handles NaN)

find returns the element; findIndex the position; use some/every instead of filter().length tricks.

sort: the comparator trap

[10, 9, 1].sort();                 // [1, 10, 9] — string sort by default!
nums.sort((a, b) => a - b);        // numeric ascending
posts.sort((a, b) => b.date - a.date);        // newest first
names.sort((a, b) => a.localeCompare(b));     // human alphabetical

nums.toSorted((a, b) => a - b);    // modern: sorted COPY (sort mutates)

sort, reverse, splice, push mutate; map, filter, slice, concat, toSorted, toReversed return new arrays. Know which is which — React state depends on it.

"[10, 9, 1].sort() — output?" catches half of candidates. Default sort compares strings.

Destructuring and spread, combined

const [first, ...rest] = queue;               // head/tail
const { password, ...safeUser } = user;       // omit a field
const merged = [...new Set([...a, ...b])];    // union, deduped
const updated = todos.map((t) =>
  t.id === id ? { ...t, done: !t.done } : t   // immutable update
);

That last line is the single most common pattern in React state updates.

Iterables and generators

function* take(iterable, n) {
  let i = 0;
  for (const item of iterable) {
    if (i++ >= n) return;
    yield item;               // lazy — nothing computed until pulled
  }
}
[...take(hugeList, 5)];

for..of, spread, and destructuring all consume the same iterator protocol; generators are the easiest way to produce it — lazy sequences, pagination, custom traversals.

Async & the Event Loop

One thread, never blocked: everything slow happens elsewhere and comes back as a queued callback. Master the queue order and async stops being mysterious.

Why async exists

The thread that runs your JS also paints the page (or serves other requests, in Node). Waiting synchronously would freeze everything — so slow work (network, disk, timers) is delegated, and completion callbacks queue up for the loop to run.

From callbacks to promises

A promise is a one-time container for a future value: pending → fulfilled or rejected, settled once, immutable after. Chaining works because every .then returns a new promise; errors skip ahead to the nearest .catch. 

getUser(id)
  .then((u) => getPosts(u))     // return value feeds the next link
  .then((posts) => render(posts))
  .catch((e) => showError(e))   // any failure above lands here
  .finally(() => spinner.hide());

async/await, and the parallel trap

async function load() {
  try {
    // WRONG when independent: 300ms + 300ms
    // const user = await getUser(); const feed = await getFeed();

    // RIGHT: fire both, await together — 300ms total
    const [user, feed] = await Promise.all([getUser(), getFeed()]);
    return { user, feed };
  } catch (e) {
    // rejection from either lands here
    throw new Error("load failed", { cause: e });
  }
}
Spotting sequential awaits that should be Promise.all is a rite-of-passage code-review question.

The combinators

Promise.all(ps)        // all values, or first rejection
Promise.allSettled(ps) // every outcome: {status, value|reason}
Promise.race(ps)       // first to settle — timeouts
Promise.any(ps)        // first to fulfill — fastest mirror

allSettled for "save what you can" batch jobs; race against a timeout promise is the classic pattern.

Micro vs macro: the actual order

After the stack empties: drain all microtasks (promise callbacks), then run one macrotask (timer, I/O), then microtasks again. Hence promises always beat setTimeout(…, 0). 

console.log(1);
setTimeout(() => console.log(2));
Promise.resolve().then(() => console.log(3));
console.log(4);
// 1 4 3 2 — burn this ordering into memory
This exact snippet appears in a huge share of JS interviews. See the JavaScript guide's output-prediction section for variants.

Cancellation and timeouts: AbortController

const ctrl = new AbortController();
fetch(url, { signal: ctrl.signal }).catch((e) => {
  if (e.name === "AbortError") return;   // expected, not a failure
  throw e;
});
ctrl.abort();                             // e.g. user typed again

fetch(url, { signal: AbortSignal.timeout(5000) }); // built-in timeout

The standard answer to "how do you cancel a stale search request?" — and the cleanup React effects should do.

The Browser

The DOM is a live tree the browser hands you; events, fetch, and storage are the APIs around it. Frameworks abstract this — interviews check you know what's underneath.

Selecting and changing the DOM

const el = document.querySelector("#list");        // first match, CSS syntax
const all = document.querySelectorAll(".item");    // static NodeList

el.textContent = "safe text";     // never parses HTML — XSS-safe
el.innerHTML = "<b>runs markup</b>";   // only with trusted content
el.classList.toggle("open");
el.append(newNode);
el.closest("[data-row]");         // walk UP to the nearest match
textContent vs innerHTML is an XSS question in disguise — say "textContent for user data" unprompted.

Events: bubbling and delegation

Events travel target → up through ancestors (bubbling). Delegation exploits that: one listener on the stable parent handles every child, present or future. 

table.addEventListener("click", (e) => {
  const row = e.target.closest("tr[data-id]");
  if (row) select(row.dataset.id);
});
// e.preventDefault() — stop the browser's default action
// e.stopPropagation() — stop ancestors from hearing it (use sparingly)

fetch, done right

async function api(path, options = {}) {
  const res = await fetch(path, {
    headers: { "Content-Type": "application/json" },
    ...options,
  });
  if (!res.ok) throw new HttpError(res.status, await res.text());
  return res.status === 204 ? null : res.json();
}
api("/api/todos", { method: "POST", body: JSON.stringify(todo) });

The interview point: fetch rejects only on network failure — a 404 resolves fine. You check res.ok yourself.

Storage: local, session, cookie

Size Lifetime Sent to server?
localStorage ~5 MB until cleared No
sessionStorage ~5 MB tab lifetime No
cookie ~4 KB configurable Every request

Storage is synchronous and string-only (JSON.stringify). Auth tokens: httpOnly cookies beat localStorage — JS (and therefore XSS) can't read them.

Timers and animation frames

const id = setInterval(poll, 5000);
clearInterval(id);                  // ALWAYS have a cleanup path

requestAnimationFrame(step);        // runs before next paint — animation JS

Timer delays are minimums, not guarantees. Forgotten intervals are the classic SPA memory leak — cleanup belongs in the unmount path (React's effect cleanup return).

Forms without a framework

form.addEventListener("submit", async (e) => {
  e.preventDefault();                        // stop the full-page reload
  const data = Object.fromEntries(new FormData(form));
  if (!form.reportValidity()) return;        // built-in validation UI
  await api("/api/signup", { method: "POST", body: JSON.stringify(data) });
});

FormData reads every named field in one call — the platform's answer before controlled components existed.

Modern Essentials

The features that separate current JavaScript from tutorial-era JavaScript.

Modules

// named — several per file, import must match (or alias)
export const parse = () => {};
import { parse as parseDoc } from "./parse.js";

// default — one per file, importer names it
export default class Store {}
import Store from "./store.js";

const heavy = await import("./charts.js");  // dynamic — code splitting

ESM is static — bundlers tree-shake unused exports. Dynamic import returns a promise and is how routes lazy-load.

Optional chaining and nullish coalescing

const street = order?.shipping?.address?.street;  // undefined, no throw
config.retries ??= 3;                             // assign only if null/undefined
onDone?.();                                       // call only if provided

?. short-circuits the whole rest of the expression; ?? respects 0/""/false as real values where || would not.

Map, Set, and their weak siblings

const seen = new Set(ids);           // O(1) membership: seen.has(id)
const cache = new Map();             // any key type, keeps insertion order
const meta = new WeakMap();          // keys held weakly → GC-friendly
meta.set(domNode, { clicks: 0 });    // node removed → entry collectable

Map over plain object when keys aren't strings, you need size, or you add/remove a lot. WeakMap for metadata about objects you don't own.

Copying and immutability helpers

structuredClone(state);            // real deep clone — dates, maps, cycles
const next = { ...state, done: true };      // shallow, one level
arr.toSorted(cmp); arr.toReversed(); arr.with(2, x);  // non-mutating variants
Object.freeze(config);             // shallow lock — dev-time guard
If asked "deep clone?" — structuredClone first, note the JSON.parse/stringify legacy trick and its casualties (Dates, undefined, functions).

Errors, done properly

class ValidationError extends Error {
  constructor(fields) {
    super("Validation failed");
    this.name = "ValidationError";
    this.fields = fields;
  }
}
try {
  save(data);
} catch (e) {
  if (e instanceof ValidationError) showFieldErrors(e.fields);
  else throw e;                     // never swallow what you can't handle
}
// wrap and keep the original: new Error("save failed", { cause: e })

Typed errors + instanceof switching + the cause option — the difference between error handling and error hiding.
